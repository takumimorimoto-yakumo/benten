# Benten: evidence-to-unsigned-route workspace (pre-image design)

Status: **desktop visual-direction candidate `review_pending`; direct-human acceptance absent**. Date: 2026-09-14 JST. This narrows the long-horizon product IA (`investigate-decide-acquire-ia.md`, removed 2026-09-24; see git history): Benten supplies public evidence and, only after separate route gates, an **unsigned route/quote handoff**. The user's external wallet or user-side agent signs and submits; Benten never holds spend authority, never labels its own handoff an order, and never claims a trade settled without independently verified chain evidence. Current repository capabilities are still read-only with **zero executable routes**; current API/MCP cannot quote, sign or send. The React Router/Vite app and shadcn primitives are intended future implementation, not present dependencies; the old Next.js UI/catalog are negative/behavioral references only. The sections below remain the **information/state contract**, while their `new-york`/ink-blue/IBM Plex visual proposal is historical and must not override the [observed CLI baseline and implementation-first handoff](shadcn-baseline-review.md).

## 1. One human job, five separate truths

The human begins by choosing an exact xStock, not by choosing a recommended stock. In one workspace they see what the token is, which public company facts actually have sources, what rights/restrictions apply, whether an exact Solana route is checked, and what **their own signer** would need to approve. They independently decide whether to act. A company fact cannot prove the token is a share, that a pool is liquid, or that a person is eligible. Benten's public-data projection contains no private upstream analysis, Benten rating, target price or “buy” judgment.

| Group | Minimum screen content | Truth/source boundary |
| --- | --- | --- |
| Token identity | Token symbol/name, exact mint with Copy, Solana network, issuer observation, distinct referenced company only when source-backed. | Registry snapshot/revision; text search is navigation only, exact mint allowlist is execution identity. Unknown program/issuer fields display unknown. |
| Public company facts | Coverage status, a small list of actual accepted facts with value, unit, full period, filing source/date and artifact as-of; `View all sources`. | One-way reviewed public artifact; only three companies currently have any source-verified facts. Legacy/no-data never receives a verification badge. |
| Instrument rights | **After copy review**, explain tracker-certificate rights versus underlying shares and link current issuer terms. In the present mock, show only `Product terms: review pending` with an official-source access point; do not paint unapproved Benten legal wording as a live claim. | Issuer legal documents and Benten legal review, independent of SEC facts. Current eligibility/distribution copy is unapproved; no trade CTA. |
| Route/quote | Exact input/output mint, venue/router/pool, checked slot/time; size-specific output/minimum, fee/slippage/impact/expiry only when audited. | Current state is unavailable; pool identity and issuer indicative price are **not** executable quotes. A future quote is per amount/owner/route and expires. |
| External authority/outcome | Handoff states “Unsigned — review in your wallet/agent”; later verified signature/status/actual raw and displayed deltas if observed. | Benten does not sign, send or claim settlement. API key is not spending authority. Unknown with/without signature, rejection and confirmed chain result differ. |

The product's visible promise is “Investigate an xStock and check an unsigned Solana route before you authorize it elsewhere,” **not** “Benten orders for you.” “Analyze” means inspect/compare source-backed public facts, not a Benten investment recommendation. External organizations' AI may consume the same bounded API/MCP facts and, in a later contract, unsigned route context; its free-text opinion and wallet/signer actions are outside Benten's validated fact boundary. Current MCP/API remain read-only, and a future unsigned route API is an explicit policy/architecture migration, not an existing tool.

## 2. Home information hierarchy and navigation

Home is a task workspace, not a landing-page brochure, static stock dashboard, pure registry table, or DEX-like fake swap. A real search/selection control and visible A–Z list coexist. The first screen explains current vs gated future abilities in short labels, while an evidence panel shows the result of a **user-selected** token. The desktop visual mock should show the **selected-state specimen** after the user chose NVDAx from exact registry results; it is not an auto-selected default, ranking or recommendation. It should carry a small “Selected by you” state label. Numeric facts in an image are illustrative only; runtime must bind accepted records.

1. Header: Benten, `Explore`, `API & MCP`, locale. No `Trade` link or wallet connect in current mode.
2. Compact job heading: `Investigate an xStock before you use your wallet`. Selected-state status: `Selected NVDAx has source-backed facts · Route checks and unsigned handoff not available yet`. Unselected and non-verified tokens need their own honest status text; never suggest all 154 have facts. No large promotional hero or feature-card trilogy.
3. Left exploration rail: visibly labeled search (`Ticker, token name, or exact mint`), `All / Source-backed facts` factual filter, neutral A–Z result count and first registry rows. Text name hits are discovery hints; exact mint is separately marked. The selected row remains visible with a textual selected marker. A-Z is not popularity. Empty/unknown/retry are in this same area, not modal detours.
4. Main selected-token workspace: exact identity and **rights-source review status** first, then **actual** public fact coverage/source rows, then route/quote status. Its main current CTA is `Open token details` for full provenance. It must **not** include USDC amount, fake price, disabled `Swap`, wallet signature prompt or `Order placed` state while route count is zero. Route panel reads `No executable route is available in Benten yet`; do not infer no external market.
5. Below first viewport: fuller registry table/list and a concise developer panel: `Read-only API / MCP for public facts today`, with setup/schema link. Future unsigned-route capability is labeled future, not a current method. Dossier deep link opens full fact/rights/source detail and preserves Home query/selection/back. A future `Review unsigned route` page is mounted only after audited route/legal/security acceptance; external wallet signing and submission happen outside Benten.

## 3. State and action map

| State | Screen truth | Action and recovery |
| --- | --- | --- |
| Initial / no selection | Real first A–Z registry rows, capability line, prompt to select; no sample recommendation. | Search or pick one row. |
| Text hit / exact mint hit | Text hit is navigation; exact case-sensitive allowlist match identifies executable subject. | Select explicitly; copy/open exact mint. |
| Zero text results / malformed mint / unknown well-formed mint | Three different messages; no fuzzy fallback, no fraud assertion. | Clear filter, edit mint or browse all. |
| Public-fact subset / legacy-only / no current row / source error | Explicit coverage and period/source; facts remain separate from product rights. | View source/limitations or retry failed read only. |
| Route not checked / pool seen but no quote / unsupported / service error | Distinct Benten route states; current UI displays unavailable with no order control. | Continue evidence inspection; no “try anyway” action. |
| Future valid unsigned handoff | Route, amount, account, venue, raw/display basis, fees, min output, expiry and `Unsigned` warning shown after separate acceptance. | Export to user-controlled wallet/agent for independent review/sign/send; a changed field invalidates handoff. |
| External submission unknown / signature known / signature absent | Benten can observe only what is supplied/verified; `submitted` is not `confirmed`. | With signature, query chain; without, manual wallet/explorer reconciliation; no automatic second send. |

The same domain states should eventually be available as minimal structured API/MCP projections. The developer panel must accurately separate `read facts now` from `unsigned route later`; it may not advertise “AI can order” while neither route nor external signer contract exists.

### Dossier contract behind `Open token details` (not yet visually accepted)

The Home's principal CTA must open a stable token detail URL resolved by **exact allowlisted mint**, carrying search/filter/scroll as return context. Dossier is a source-and-identity work surface, not a second promotional page or an acquisition form. The desktop `1440 × 900` order is: compact breadcrumb/Back to results; token symbol/name and **full exact mint** with a `Copy mint` control plus `Solana` network; two clearly separated identity blocks for observed registry token/issuer fields and source-backed referenced company (or `No source-backed company identity`); public-fact coverage/status; accepted fact rows grouped by report period, each with value, original unit, period boundaries and source link; instrument-terms/eligibility review state with official issuer-document link; Benten route status; read-only API/MCP deep link. The observed registry issuer address, when present, must be shown **in full with Copy** in a labeled disclosure in the token-identity block, not merely linked away; the user needs to compare the actual address while verifying token identity. It is a registry observation, **not** a guarantee of the product's legal issuer, rights or eligibility. If absent, say `Issuer address not in this registry snapshot`. At `390 × 844`, the same groups stack in that order, facts become labeled rows rather than a horizontally scrolling four-column table, and long mint/issuer address wrap while their Copy controls stay visible. No fixed/sticky trade control. First viewport must show identity, full-mint access and evidence coverage; route can follow in natural scroll but must not be buried behind developer setup.

Concrete selected NVDAx specimen copy: `NVDAx · NVIDIA xStock`; `Solana mint` with full registry string and `Copy mint`; `Registry issuer field` (address only if present, with registry snapshot/as-of); `Source-backed company identity: NVIDIA CORP` with SEC identity source; `2 previewed — view all accepted facts` with the actual artifact-driven total; `Revenue · USD 215.938B · FY2026, Jan 27 2025–Jan 25 2026 · SEC 10-K filed Feb 25 2026`; `Total assets · USD 206.803B · As of Jan 25 2026 · same filing`. These are design specimens checked against the bundled artifact, not hardcoded runtime values or token prices. Show other accepted facts from the artifact rather than implying only two exist. `Product terms: review pending` remains separate from company filings, and `Benten route: unavailable — no executable quote here yet` remains distinct from any external market. Do not put buy/swap/wallet controls on Dossier while execution gates are closed.

State contract: `source_verified` shows accepted current fact rows and filing metadata; `legacy_only` labels unverified historical data and must not appear in the verified table; `no_data` says `No source-backed company facts are available for this token in the current snapshot` without implying negative company quality; `source_error` preserves token identity and offers `Retry public facts` without relabeling stale facts as fresh; `unknown/malformed mint` renders not-found or invalid-input guidance with `Back to registry`, never a fuzzy substitute; `registry row missing` is a true 404 after exact-mint lookup; `terms_pending` shows official-document link plus review state, not invented entitlement; `route_unavailable` shows Benten's capability limit and no transaction CTA. On Back, restore selected row/query/filter/scroll; direct links may start with no Home context and use `Browse registry`. Every source link uses actual accepted `filing_url` with visible form/filed date and external-link indication; broken source links are an explicit error state, not silently dropped. ### Future unsigned-handoff skeleton (not a present screen)

Only after a checked pool, executable size/owner-specific quote, legal/security gates and contract approval may a separate review surface expose exact input/output mints, venue/pool, network/account, raw/display amount basis and multiplier as-of, quote slot/time/expiry, fees/slippage/minimum output and `Unsigned — review with your own signer`. This conditional state is a future architecture obligation, not a drawn or implemented screen.
