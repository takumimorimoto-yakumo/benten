# Public evidence and unsigned acquisition tool contract

Status: **Meteora-first proposed contract; implementation/live evidence unverified; acceptance recorded separately** (updated 2026-09-16). No proposed v3 fact endpoint, quote/purchase BFF, owner quote/context endpoint, transaction template, key, order or runtime connector in this document is implemented or authorized for release. The earlier external-agent boundary remains decided; the later [human browser execution decision](../docs/decisions/user-authorized-browser-execution.md) proposes one narrower future profile. This specification does not alter present snapshot-only facts or no-sign/no-send rules.

For **Benten facts/analysis v3 only**, one domain service constructs a strictly validated DTO before HTTP or current/future local stdio MCP presenters serialize it. HTTP returns that DTO in JSON; MCP `structuredContent` contains the same domain fields and `content` carries a short factual, safety-equivalent text with the same revision/status/source—not a second inference engine. Transport metadata such as HTTP status, MCP `isError`, correlation and rate headers may differ. Tests compare the domain DTO byte-for-byte after canonical JSON normalization for the same fixture, while preserving the intentionally different **existing** v2 MCP malformed-selector text behavior. The external connectivity owner separately has one versioned quote/context DTO across its HTTP and any later network MCP transport; Benten does **not** shadow those adapters in the initial mode. All new inputs and outputs reject unknown keys and overlong strings. Never return private calculations or complete internal source files.

`GET /api/v3/xstocks` accepts only optional `ticker` **or** `mint` (mutually exclusive, exact registry resolution), `covered_only=true|false`, `source_verified_only=true|false`, `limit` and `cursor`; repeated/unknown/empty query keys are 400. It never accepts a fuzzy symbol/name search as a route identity. Entries are sorted by canonical ticker then mint. Recommend default `limit=50`, accepted integer range `1..100`; a response contains `items`, `next_cursor: string|null`, `total_matching`, applied filters and `artifact_revision`. The opaque base64url cursor carries version, artifact revision, filter digest and last ticker/mint; it is **not trusted**: decode with a length cap, validate every field and registry identity, and reject changed revision/filter or malformed cursor with 400/409 as applicable. The current 154 identities need **four** default pages, but that is not a permanent market-size promise. Home's proposed 20-row UI pagination is a separate presentation choice; no API page size is derived from it. The MCP list tool takes the same selectors/limit/cursor and returns the same domain page. Precedence is strict structure/cursor syntax first (`invalid_input`), then identifier syntax (`invalid_input` for malformed mint), then exact registry resolution (`unknown_ticker`/`unknown_mint`, HTTP 404), **then** covered/source filters (a known filtered-out identifier yields a successful empty page with `total_matching: 0`). This preserves the v2 unknown-identifier distinction without leaking an alias through a filter. A selector and cursor together are invalid; canonical tickers may use only the existing ASCII case-normalization before exact allowlist resolution, while mints remain case-sensitive.

The future **Benten facts/analysis** HTTP presenter maps `invalid_input` to 400, `unknown_ticker`/`unknown_mint` to 404, rate exhaustion to 429, dependency/timeout to 503/504, and a known asset with genuinely unavailable facts to **200 with typed `unavailable`**. Bounded public-analysis is anonymous; it has **no 401 bearer branch** in this initial proposal. The **external owner direct API** separately maps missing/invalid individual caller token to 401, disallowed consumer policy to 403, rate exhaustion to 429, provider/DB failure to 503/504 and in-flight quote expiry/route change to 409 with `quote_context_expired`/`route_state_changed`. A client must inspect the tagged status, not HTTP 200, before any handoff; there is no saved quote ID or server-side later-expiry transition. Unsupported method is 405. Benten same-origin ingress uses longest-prefix precedence: `/api/acquisition/**` goes only to the fixed quote-BFF origin, all remaining `/api/**` goes only to the fixed facts API origin, known static assets/documents follow, then canonical 308 and actual HTML/data 404. Both rewrites preserve the complete path and query; neither origin is caller-selectable. Unknown acquisition paths never fall through to facts or HTML, and direct BFF origin requests fail closed unless a deployment allowlist validates the proxy's Host/forwarded-host and same-origin Origin. API v1/v2 status/envelope precedence remains governed by [api-v2](../docs/api-v2.md), not these v3 proposals.

## 3. Exact schemas and provenance

These are proposed strict runtime schemas, not TypeScript-only assertions. Benten **facts/analysis** DTOs live in one public contract package and include `schema_version`, `artifact_revision`, tagged `status`, `data` or reason, and factual disclaimer. The independent owner has its **own** single contract package for owner-independent `OwnerIndicativeQuoteV1` and owner-bound `OwnerContextV1`; both use `consumer_policy_revision`, `route_policy_revision`, `observed_slot`, `observed_at`, `provider` and `expires_at` where their tagged branch permits, while Benten `artifact_revision` is absent from generic owner wire. `BentenIndicativeQuoteV2` adds the artifact revision to the owner quote projection without replacing either owner policy/market clock. An optional later unsigned `ContextV2` alias, if separately approved, does the same for `OwnerContextV1`. JSON numbers are only for bounded slot/count/percent values; money and token quantities use canonical base-10 integer strings/fixed-scale rationals, never floating-point amounts. An unavailable unreviewed route carries null observation/revision, not invented evidence.

| Schema | Required fields and rules |
| --- | --- |
| `IdentityV3` | Exact `mint`, `ticker`, `symbol`, token name, registry source URL/as-of/artifact revision; token issuer and reference company are separate, with `underlying_company: null` when unverified. `token_program: unknown` cannot pass a quote gate. |
| `FactCoverageV3` | `source_verified_fact_count`, per-fact availability for the five accepted monetary fields, `latest_period_end: string|null`. Product rights, route status and caller eligibility are **not** fact coverage fields. A count does not imply all statements or legal rights. |
| `EvidenceV3` | `identity`, `coverage`, accepted `verified_facts` with `value`, USD `currency`, scale/unit, `period_ref`, `source_ref`; matching period start/end/kind and filing accession/form/filed-at/public URL. No `legacy_snapshot` member exists in this v3 schema. Source-verified subset only; missing fact is absent with a reason, never interpolated. |
| `PublicAnalysisRequestV3` | Exact one `mint`; `measures` is a nonempty unique subset of `net_margin` and `liabilities_to_assets` (pilot taxonomy), max two. No free-form prompt, weights, target price, portfolio or recommendation field. |
| `PublicAnalysisV3` | Per measure: `available` with `numerator` as canonical signed base-10 integer string and `denominator` as canonical positive base-10 integer string; reduce by gcd, put sign only on numerator, forbid `+`, leading zeros and negative zero, and normalize zero to `0/1`. BigInt arithmetic; source values stay within existing safe-integer artifact contract. `display_decimal` is **exactly six fractional digits**, rounded half away from zero, derived for presentation only; a display change does not alter the rational. Include period/source refs for both operands and calculation ID/version. Otherwise `insufficient_evidence` with missing operands/period mismatch reason. Net margin uses parent net income/revenue from the **same duration period and currency**, revenue >0; liabilities/assets uses the **same instant period and currency**, assets >0. Negative net income is permitted; no cross-period joining. Results are arithmetic facts, not valuation. |
| `RouteCapabilityV1` | Always include exact `cluster`, `genesis_hash`, allowlisted `output_mint`, fixed input USDC mint, `product_terms_status: unreviewed|reviewed` and a **size-independent** status. Discriminated union: `not_reviewed` has `route: null`, `checked_slot: null`, `checked_at: null`, `route_policy_revision: null`; `pool_verified_only|quote_unavailable` require an observed `route` object with exact venue/program/pool/mints/token programs/vaults and nonnull revision/slot/time; `temporarily_unavailable|disabled_by_policy` require a reason and may carry either an observed route with those complete fields **or** `route: null` with all observation fields null. No field is fabricated for an unreviewed mint. Product terms review is a separate public policy record, default `unreviewed`; it does **not** determine caller eligibility. The GET has no amount/owner and **cannot** assert `unsigned_context_ready`; only the size- and owner-bound POST may return `quote_context_ready` after A4/A5/A6. |

For Benten **facts** selectors, path `{mint}` is percent-decoded once and resolved by the exact registry allowlist; `unknown_mint` and malformed `invalid_input` remain distinct. In the **initial direct owner API**, the authenticated caller supplies exact input/output mints and raw amount within its server-owned registered consumer policy; no ticker alias, user-supplied pool, program, fee recipient, generic symbol or arbitrary RPC URL is accepted. At a quote boundary, the owner independently verifies mint account owner, decimals, extensions, reserve/vault mint and authority, pool program/discriminator/status, verified mainnet genesis and quote-source slot. Its reviewed **generic route-policy record** is distinct from Benten's reviewed **consumer product policy** (exact supported mint, fixed pilot input, permissible route/mode/amount, product wording); both must pass. Neither all 154 registry entries nor a caller-provided policy is an execution allowlist. Both revisions require review/version bump; unsupported assets fail closed without guessing another DEX. The capability enforces the Benten consumer policy against its **owner-issued individual caller token** bound to that consumer and policy revision, not a spoofable request body/header; a different registered consumer cannot reuse that token or loosen its ceiling.

Fact freshness uses distinct clocks: `registry_as_of`, artifact `published_at`, filing `filed_at`, fact `period_end` and any route `observed_at/slot`. Display all applicable clocks. No “real-time financials” badge or blanket freshness TTL is inferred from an artifact revision. A newer producer candidate is accepted only by the existing four-file checker, source ledger and dedicated artifact release; API/MCP/static output deploy from the **same** revision. If artifact and API revision differ, return a typed service failure rather than mixing facts.

## 4. Unsigned context and fail-closed lifecycle

Owner `/v1/quotes` accepts strict `{schema_version:"1.0",cluster,input_mint,output_mint,input_raw,max_slippage_bps}` with no owner address, venue, pool, revision override or bytes. Its `OwnerIndicativeQuoteV1` response contains `status:"indicative_quote"|"candidate_unverified"|"unavailable"`, exact route and both policy revisions, observed slot/time, expiry, raw input debit/gross/net/minimum, lossless `FeeComponentV1[]`, quote-time display basis, `economic_completeness`, correlation digest and `capability:"not_authorization"`. It never implies owner/ATA/template readiness. Unknown required token/DEX/integrator economics or debit/net/minimum blocks `indicative_quote`; ancillary network/rent/tip may remain explicit unknown with `economic_completeness:"partial_ancillary"` and no bytes.

The union is exact. `indicative_quote` requires nonnull reviewed `route`, `consumer_policy_revision`, `route_policy_revision`, positive `observed_slot`, `observed_at`, `expires_at`, canonical positive `input_raw`, debit/gross/net/minimum raws satisfying the §4 inequalities, complete fee-kind coverage, `economic_completeness:"complete"|"partial_ancillary"`, `correlation_digest` and no `reason`; it forbids every owner/template field. `candidate_unverified` requires a nonempty typed `reason`, may preserve a structurally valid untrusted route/economic claim, but sets every unproved field null and cannot claim a reviewed route revision or positive readiness. `unavailable` requires a typed reason and has `route`, observation, revisions, economics, fees and correlation all null/empty as specified by the runtime schema. Every branch rejects unknown keys. Owner HTTP errors use exactly `{schema_version:"1.0",error:{code,retryable,correlation_digest}}`; the BFF error projection uses exactly `{context_version:"2.0",error:{code,retryable,correlation_digest}}`. `code` is typed, `retryable` is an owner boolean, and `correlation_digest` is a bounded server-generated opaque digest. Neither envelope carries upstream text or economics. The BFF preserves HTTP status and all three error members losslessly and never maps an HTTP error into a data branch. Frozen owner and BFF fixtures cover owner-address-absent positive, candidate, unavailable, partial ancillary fee, required-economic unknown, wrong/missing revision, wrong minimum, unknown key, collapsed-fee rejection and exact error-envelope equality.

The Benten BFF request is stricter still: `{context_version:"2.0",output_mint,input_raw}` only, with cluster/input mint/mode fixed by server policy. Maximum body 2 KiB; duplicate/unknown keys and noncanonical integers fail 400. It maps `OwnerIndicativeQuoteV1` losslessly into `BentenIndicativeQuoteV2`: the same tagged status, route/economic/fee/policy/slot/time/expiry fields plus Benten `artifact_revision`, with no owner address or bytes. It never changes candidate/unavailable to success and emits `Cache-Control:no-store`.

`POST /api/acquisition/session` accepts no body and only after exact same-origin Origin/Host validation. A successful response is `201` with `{context_version:"2.0",csrf_token:<base64url>,request_nonce:<base64url>,expires_at:<ISO>}`, `Cache-Control:no-store`, and `Set-Cookie: __Host-benten-acquisition=<opaque 256-bit random id>; Max-Age=600; Path=/; HttpOnly; Secure; SameSite=Strict` with no Domain, matching the [__Host cookie requirements](https://httpwg.org/http-extensions/draft-ietf-httpbis-rfc6265bis.html#name-the-__host-prefix). Each quote requires exactly one case-sensitive `__Host-benten-acquisition` cookie plus one `X-Benten-CSRF` and `X-Benten-Request-Nonce`; duplicate, missing or malformed values are rejected before admission and never resolved by header order. The issuer, validator and sole state writer are `apps/acquisition-bff`; the browser cannot mint or select session state. Session issuance itself is charged to **5/minute and 100/day per privacy-HMACed source IP plus 1,000/minute global** before allocating a record.

The production recommendation is a dedicated **single-shard Redis 7-compatible primary with reviewed failover**, not process memory or an unproved Redis Cluster. This paragraph is the sole normative admission-state definition. Exact keys are `bq:s:<session_hash>` for session/epoch/CSRF metadata, `bq:n:<session_hash>:<nonce_hash>` for one-use nonce state, `bq:l:<admission_id>` for admission/lease state, `bq:sp:<session_hash>` for the active-admission pointer, `bq:r:<scope>:<window_kind>:<window_start>:<subject_hash>` for fixed windows, and `bq:capacity:<kind>` for `sessions|admissions`; no other `bq:` family is valid. Values contain only HMAC-SHA256 verifiers, expiry/auth epoch, an unguessable lease token, admission state or bounded integer. A versioned Lua script loaded and invoked by pinned SHA (`EVALSHA`; reviewed `EVAL` load fallback only) atomically validates the active 10-minute session and CSRF, CAS-consumes the issued nonce, creates the next nonce, acquires a six-second lease/admission, charges counters, and enforces quote ceilings of **6/minute and 60/day per session, 30/minute and 300/day per privacy-HMACed source IP, 300/minute and 10,000/day global**, plus one active admission/session and 1,000 globally. Capacity is 50,000 active sessions and 1,000 active admissions. Overflow is 429 without eviction. Rate charges are not refunded; a compare-and-transition Lua release/reaper accepts only `admitted -> released|expired`, so only one winner releases the lease. Session/nonce state expires after 10 minutes, a lease after six seconds, and counters after the window plus one minute. A reconciliation job derives capacity from live session/admission keys; uncertainty or store/reaper/failover outcome returns 503 before any owner call. Restarting one BFF replica cannot restore a nonce, extend a session or lose the shared lease. After Redis restore/failover, the BFF increments `session_auth_epoch`, invalidates pre-event sessions and verifies counters/admissions before reopening; it never assumes replicated atomic completion. Redis Cluster/sharding is a later scaling decision requiring one-slot key design or a different transactional admission primitive and equivalent race tests. The next nonce is returned only in `X-Benten-Request-Nonce` after a validated response; a lost response requires a new session. The source IP is accepted only from one deployment-configured trusted ingress identity; direct-origin/untrusted forwarded headers are rejected, never used for quota identity. Session/IP HMAC keys live only in the BFF secret store and carry a key ID/auth epoch. **Every routine or emergency rotation atomically advances the epoch and immediately rejects all prior-epoch sessions**; prior key material may remain for at most 10 minutes solely to classify/redact rejected traffic and is never accepted for admission. Sessions are never migrated. Raw IP, quote, wallet, owner token and order data are never stored. A deterministic in-memory adapter is **test-only** for local F0-Q; multi-instance/provider release requires this Redis adapter, atomic script hashes, two-replica/restart/reaper/failover/restore proof and fail-closed store-outage behavior. No Redis service or credential is created by the local capsule; activation and measured scaling are later gates. These numeric limits are pilot defaults, not funding or identity limits.

The owner call has a 5-second hard deadline and no automatic retry. Missing session is 401, CSRF/replay/policy is 403 or 409 as typed, quota 429, route/expiry 409, admission-store or owner unavailable 503 and timeout 504. The server-held Benten consumer token is audience/scope/policy-bound, redacted and never returned or embedded in Web assets.

Owner `/v1/unsigned-contexts` accepts strict `mode:"quote_only"|"unsigned_template"` plus exact `cluster`, mints, `owner_address`, canonical `input_raw` and `max_slippage_bps`; the owner policy fixes the Benten pilot. It re-reads/requotes and may not accept a BFF quote as authority. No `quote_id`, client price, user-selected venue, referrer, fee account, blockhash, caller/consumer ID, policy revision override or prebuilt instructions are accepted. The pilot bounds remain configurable 1–100 USDC and 1–100 bps guardrails, not spending limits. `owner_address` is not proof of wallet control, residence or eligibility and is not logged/persisted by default.

**Frozen proposed wire (not implemented):** owner direct API emits `OwnerContextV1` with `schema_version: "1.0"`; a later, separately approved Benten consumer presentation, if ever built, uses `context_version: "2.0"` and maps this owner result **losslessly**. The earlier draft `context_version:"1.0"` and singular `fee` are superseded before deployment, so there is no existing public v1 compatibility to preserve. The owner result does **not** carry Benten `artifact_revision`; Benten would add its reviewed artifact revision only in a future product projection, without treating it as quote freshness. Both schemas retain `capability:"not_authorization"` and an explicit factual disclaimer. `consumer_policy_revision` and `route_policy_revision` are distinct, exact strings/nonnegative revision identifiers; null only when that policy/route was not observed. A caller cannot supply either revision as authority.

`OwnerContextV1.status` is `unavailable | candidate_unverified | quote_observed | quote_context_expired`; `quote_observed` is a **research state**, not by itself a Benten-ready state. A future Benten `ContextV2.status` is `unavailable | candidate_unverified | quote_context_ready | quote_context_expired`: map owner `unavailable`→`unavailable`, `candidate_unverified`→`candidate_unverified`, and owner `quote_observed`→`quote_context_ready` **only** after the acceptance table below. Otherwise downgrade to `candidate_unverified`/`unavailable` with a reason; never upgrade an unknown by HTTP 200. `quote_context_expired` is emitted only for an **in-flight** request that lost freshness before response; previously returned data expires in the caller's possession. Owner HTTP 400/401/403/409/429/503/504 maps to the same semantic code in any later Benten adapter; it may not turn auth/policy failure into a ready 200. The current Benten v1/v2 envelopes remain unaffected. A future HTTP/MCP wrapper must use the same validated domain DTO; no local stdio tool is extended now.

Hash covers canonical unsigned message; audit manifest lists all programs/accounts/signers/writable roles; no signatures or success assertion. |

`FeeComponentV1` is a strict discriminated union. `known` requires `{kind,status:"known",mint,raw,basis,source}` with a valid mint, canonical nonnegative raw string, nonempty calculation basis and dated provider/onchain source. `unknown` requires `{kind,status:"unknown",mint:string|null,raw:null,basis:string|null,source:string|null,reason}`; `not_applicable` requires `{kind,status:"not_applicable",mint:null,raw:null,basis:null,source:string,reason}`. Unknown/not-applicable **never** masquerades as zero. A reviewed route defines required, uniquely keyed kinds: `dex_lp_protocol`, `input_transfer`, `output_transfer`, `integrator`, `network_priority`, `rent`, `tip`. Separate mint rows are retained for multi-mint charges; unexpected or duplicate `(kind,mint,source)` and absent required kinds fail validation. `source` is provenance, not arbitrary provider text to execute. Additional required kinds demand a **versioned contract amendment**, not silent dropping. All fee rows and original known/unknown reason survive owner→future Benten mapping byte-for-byte after canonical JSON normalization.

| Evidence at response time | `quote_only` disposition | `unsigned_template` disposition |
| --- | --- | --- |
| Reviewed route and consumer policy, exact source slot/freshness, owner/ATA/hook, token program/decimals/multiplier, known gross/net/debit ceiling/**net min**, every **input/output/DEX/integrator** fee known or `not_applicable`; only future network/priority/rent/tip cost unknown | `quote_context_ready` **only as informational quote**, with those ancillary fee rows `unknown`, `economic_completeness:"partial_ancillary"`, no execution or total-cost claim | `candidate_unverified`/unavailable; no bytes, because full charged-account economics are not audited. |
| All selected route-required fee rows known or `not_applicable`, independent price source known and within a reviewed bound, exact instruction/account/ALT/hook/signer/fee payer/no-send audit and separate expiry + block-height checks | `quote_context_ready`, `economic_completeness:"complete"`, no bytes | `quote_context_ready` with **audited unsigned** bytes and manifest; external signer still independently revalidates. |

| Owner result is `unavailable`/`candidate_unverified`, or provider timeout/429, owner token revoked, unsupported policy | Preserve tagged unavailable/candidate or HTTP error; do not infer success | Same; never automatic retry as a transaction. |

Fixture vectors: (a) gross `1000`, output transfer fee `10` known and other charged rows known/not-applicable → net `990`, net min `980` may pass quote-only; mapping that drops fee or reports min `995` is rejected. (b) same gross with output transfer `unknown` and net `null` → candidate only, never ready. (c) DEX fee `2` input mint and network fee `5000` lamports in a **different** mint remain two rows; one summed `fee` is rejected. (d) ancillary network fee unknown → partial **quote-only** may pass with explicit unknown; template cannot. (e) wrong/absent consumer revision, stale source slot, `min_output_raw > net_output_raw`, known fee with null raw, duplicate/omitted required kind and candidate→ready promotion all fail. These are synthetic contract fixtures, **not live NVDAx economics**.

The quote is per-request and disposable, with no server order ledger or implicit replay token. Recommended **wall-clock** `expires_at` is the earlier of a documented provider time deadline and a locally configured 15-second ceiling. For an unsigned template, `last_valid_block_height` is a **second independent validity condition**: the observed chain height must still be within that bound at handoff and at the external signer's own validation. Never convert block height to a guaranteed ISO expiry or treat a future `expires_at` as proof that the blockhash remains valid. Missing provider timing/height evidence needed for the chosen mode returns `unavailable`. Never accept an old quote as input to the template operation: re-read route state and re-quote at the same or newer context, then audit the newly built message. A changed pool, route revision, mint program, hook, multiplier, amount, fee, account meta, blockhash, wall-clock deadline or valid-height bound invalidates the context. Do not automatic-retry a failed/unknown operation as an order. For an external submitter's timeout without a known signature, Benten offers no recovery verdict; that submitter must reconcile wallet/explorer/chain before considering a new trade.

An `unsigned_template` passes only if every instruction, CPI-relevant program/account meta, address-lookup table resolution, writable account, signer, fee recipient, transfer-hook extra account and destination is an exact reviewed role; there are no hidden transfers, unrelated signers, nonzero signatures or unexpected compute/tip/referral instructions. Validate exact raw USDC debit ceiling and NVDAx minimum output semantics against the actual DEX instruction, not a displayed quote. Re-run a no-send simulation only as **negative evidence**; dummy-owner simulation cannot prove wallet authority, final fill, fees or external policy. If a safe deterministic audit is not possible, ship `quote_only` or nothing. Opaque provider-serialized bytes are **never** labelled safe merely because they deserialize. The external signer must independently revalidate its actual transaction and own consent/sign/send/recovery.

Meteora is the selected **first evidence target**, not a proved runtime route. Use it only if the pinned SDK/license, exact pool, Token-2022 behavior, Node runtime interop, depth-at-size, raw minOut and exhaustive transaction audit pass no-send tests. The SDK builder's internal account/blockhash reads and compute-estimation fallback must be instrumented; the final message needs independent fresh account/policy validation and a fail-closed simulation. Browser wallet interop is a separate gate, not proof supplied by the owner Node adapter. Raydium CLMM remains read-only evidence with unresolved GPL SDK adoption. A Jupiter onchain-router `/build` path is now the sole bounded purchase alternative if direct Meteora fails, but only after exact one-hop/one-pool route, current ABI/CPI/ALT, Token-2022 net-min and decoded-message audit; Meta-Aggregator/RFQ or provider `/execute` is not silently substituted. If both fail, return `unavailable`.

### Human browser purchase delta

`OwnerContextV1` remains the generic owner-direct proposal. The purchase MVP uses the stricter `OwnerAuditedPurchaseContextV1` and Benten projection defined only in [User-authorized browser execution v1](contracts/user-authorized-browser-execution-v1.md). The quote BFF token cannot call it. A separately scoped purchase service caller may request the one fixed consumer route and owner-sensitive account build; it cannot select provider/program/pool/RPC/referral/fee recipient or reach submit/admin surfaces. Owner and BFF still never receive signed bytes or call send.

The isolated browser must use the pinned Wallet Standard sign-only feature that returns signed bytes, re-audit the exact message after signing, persist its known signature and blockhash bounds before one direct browser RPC submission, and reconcile only that signature. Opaque combined sign-and-send, server/provider relay and automatic resend are excluded. The browser-local receipt is not a Benten server order ledger. Plan acceptance, unsigned bytes or simulation success alone never enable Buy. The exact official feature identifier and source digest live in the private feasibility receipt until the scoped publication scanner is itself reviewed.

## 5. Auth, operations, cost and rollback

Existing public v1/v2 GET and local stdio MCP require no new credential. Recommended v3 **list/evidence GET and bounded public-analysis POST** are anonymous: ingress IP/global quotas, strict selectors/body/CPU cap and abuse circuit, pilot **60/minute** list/evidence and **20/minute** analysis subject to NAT/cost measurement. Analysis is at most two deterministic arithmetic measures over already approved facts; its independent A2L advice/legal gate stays. No Benten bearer store or Solana-owner authentication is introduced for analysis. An external server/agent is directly authenticated by the owner API: owner admin issues one opaque token per `consumer_id + caller_id + active policy revision`, owner API validates it and enforces per-caller/global quotas and exact reviewed policy. The owner token is transported only as TLS `Authorization: Bearer <token>`, never query/body/cookie/browser bundle. Its proposed pilot quota is **30/minute, 1,000/day and 10 concurrent per stable `(consumer_id,caller_id)`** plus global RPC budget. Rotated/simultaneous tokens share those limits. The selected BFF instead authenticates as one stable service caller `benten_quote_bff` under a distinct quote-only scope and proposed owner ceiling of **300/minute, 10,000/day and 1,000 concurrent**; it cannot borrow individual quota or request unsigned contexts. This owner ceiling does not replace the finer anonymous-session admission above. Both sets are unverified capacity defaults. Missing/bad bearer is 401 and policy violation 403; a token does **not** prove wallet control, jurisdiction, eligibility, consent or spending authority. An owner admission remains durable until one CAS release/expiry, and rate charges are not refunded on unknown provider outcome. Owner DB/validator outage fails closed. Benten does not issue or validate owner tokens; the quote-only BFF stores its one scoped **server-side** token and relays only its fixed request after admission. Browser unsigned-context access and Benten HTTP/MCP context aliases remain disabled; external agents call the owner directly. Do not mint/distribute a token in this local phase. Current local stdio MCP uses its local process trust boundary; remote MCP authentication/hosting is a separate decision. Quota identity is not legal review. Provider unit prices and traffic mix remain to be measured.

Benten's factual artifact storage is the existing four immutable JSON files; Benten proposes **no caller-token, server order or quote database**. The external capability alone owns access-controlled **individual caller-token** digests/revocation, consumer policy, atomic quota and sanitized audit state in a database isolated from private trading storage and roles. The BFF's separate Redis namespace contains only the expiring abuse-control keys above. Any optional reusable quote intermediate is owner-side, disabled by default and limited to owner-independent, route-revision/size/slot/expiry-bound evidence. Owner address, ATA resolution, account metas, blockhash-dependent unsigned transaction bytes and audited template are **never shared across users or cached as a reusable quote**. Benten servers persist no owner address, intent, order, key, signature or transaction bytes. The future isolated browser may persist only the bounded public receipt/tombstone defined by the purchase contract; it is never uploaded. Both server systems log only sanitized schema/revision, reason, provider, slot, latency, quota/circuit state and anonymous correlation; suppress wallet address, holdings, bytes, signature, raw signed payload and private analysis. On RPC mismatch, provider 429/5xx, stale quote, audit failure, legal disable or revision skew, the owner circuit returns `temporarily_unavailable`/`disabled_by_policy`, while Benten's facts remain available. Do not reuse a stale quote under outage. Recovery is owner-side provider/route revalidation for an **unsigned** intent; after signing, the browser reconciles only its known signature and never resends. A restored owner policy DB must invalidate all pre-restore tokens before reopening. Quote and purchase BFF routes roll back independently. No Benten server transaction reconciliation or order RPO exists.

Capacity gate: at the proposed 1,000/day/**stable owner caller identity** ceiling, `N` distinct active callers can request at most `1,000N` contexts/day before global-consumer controls; multiple or rotated tokens for one caller do not multiply that ceiling. Actual RPC fan-out per quote, burst behavior, p50/p95 latency, 429 rate, hosting invocations, cache hit rate and monthly low/base/peak spend must be measured with **dated** vendor prices. “Free tier” is not zero-cost capacity. User/provider transaction fees, account rent and execution incident costs are external and must not be booked as Benten-covered. A paid RPC/provider selection or account/credential setup is not authorized here.
