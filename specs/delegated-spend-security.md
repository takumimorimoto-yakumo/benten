# User-owned xStock agent authorization: Benten tool boundary and gates

Status: **Meteora-first proposed security plan, no-effect; implementation/live evidence unverified; acceptance recorded separately** (2026-09-15). Spending permission remains owned by the user and chosen external wallet/agent/provider, **not Benten**. The planned browser path is quote-only through a short-lived Benten session/BFF; external agents separately request audited unsigned context from the connectivity owner. Benten does not grant, custody, sign, submit, revoke, reconcile or guarantee an order. Current snapshot facts and no-sign/no-send rules remain controlling. This document creates no endpoint, credential, funds or external effect.

## 1. Verdict and evidence levels

**Benten-operated autonomous spending is out of scope, not a universal technical prohibition on external agents.** Today the public Web/API/MCP offer bounded read-only facts; code for explicit-connect, read-only wallet holdings exists but is not mounted in current app routes. The non-exported `spend-policy-draft.ts` is implemented local syntax/arithmetic validation, not a current API/MCP tool and **not spending authority**. Future Benten tools may offer exact-mint, source-marked factual analysis and unsigned acquisition context after separate gates. The user/external stack may independently arrange signer/delegation and execute; Benten cannot represent that grant as vetted merely because a wallet is connected or an API key is present. No Benten grant, signing, sending or mainnet trade is authorized.

## 2. Actors, threats and non-bypass invariants

Actors: user/beneficial owner `O`, external agent `A`, user-selected wallet/provider `W`, Benten public read/tool service `B`, exact secondary DEX program/pool `D`, RPC/host `R`, and issuer/legal authority `I`. `O` and `W` own grant, key custody, signing and revocation; `A` owns its execution key and submission infrastructure. `B` may expose public facts, bounded analysis and later unsigned context, but never handles either private key or becomes a spend authority. A Benten-operated program vault is **not** an accepted component of this product.

Threats at `B`: malicious API caller, private-data exposure, false token identity, stale/malleable quote, malicious pool/account metas, hidden fee recipient or signer in a proposed payload, Token-2022 scaled-UI confusion, unsupported legal copy, or a UI/API that implies wallet connection equals consent. Threats at the external boundary: compromised agent key, weak delegate/funded wallet, provider root bypass, duplicate submission, policy upgrade/revocation race and unknown outcome. Benten can fail closed on its **own tool output**; it cannot enforce or attest an external provider's policy or recover its transaction by disabling a Benten endpoint.

Benten non-bypass conditions: (1) exact allowlisted mint/network, issuer-versus-reference-company distinction, and source/as-of on every public fact; (2) wallet connection never requests signature/delegation and never exposes a secret; (3) any unsigned context binds exact mints/token programs/DEX accounts, raw amounts, minimum output, fee recipient, quote slot/expiry and scaled-UI basis; (4) no extra signer, transfer, arbitrary remaining account, stale quote or unverified route is handed off as approved; (5) status says `not_authorization`, never `active_policy`, `order_submitted` or `safe_auto_trade`; (6) failures return an explicit unavailable reason. The external signer must independently audit and enforce its own transaction/policy; Benten cannot collapse this handoff.

## 3. Current and future tool contracts (no execution endpoint)

Current public API/MCP provides snapshot-only registry and financial facts with strict allowlist; it has no wallet-grant, order, quote, intent or signature endpoint. Current explicit-connect wallet/holdings components are code assets only, not mounted routes. A future bounded factual-analysis tool may transform only accepted public facts with source IDs, period/unit alignment and `insufficient_evidence`; it must not expose private analysis, a rating or a trade recommendation. No public runtime connector to upstream private data is introduced by this plan.

Two future surfaces stay separate. Benten's session/BFF returns only owner-independent `indicative_quote` economics, exact revisions/slot/expiry and `not_authorization`; it accepts no owner address and returns no transaction bytes. External registered agents call the owner directly for an owner-bound unsigned context. The [unsigned tool contract](unsigned-acquisition-tool-contract.md) is the sole wire SSOT. Any template requires every instruction, account/signer/ALT, Token-2022 hook and fee recipient to pass before bytes; the external signer revalidates independently. Neither surface extends existing v1/v2 or local read-only MCP.

Only the **deferred optional Benten unsigned-context alias** has response state `unavailable(reason) | candidate_unverified | quote_context_ready | quote_context_expired`, always paired with `not_authorization`, as specified by the [unsigned tool contract](unsigned-acquisition-tool-contract.md). The selected quote-only BFF instead uses `indicative_quote | candidate_unverified | unavailable` and never returns bytes. `quote_context_expired` means expiry **during a single unsigned-context request**, not a stored quote-state transition; a caller must discard a previously returned response after its `expires_at`. Before a request there is no context response (`not_checked` is only a local presentation state, not an API literal). A route's separate `not_reviewed` state maps to context `unavailable(route_not_reviewed)`, never to ready. It has **no Benten policy state or order state**. An optional later read of a user-provided signature could report `chain_unverified | pending | finalized | failed | unknown`, only with cluster/slot/finality and verified actual raw deltas; this is a separately reviewed read-only feature, not Benten submission or reconciliation ownership. The external signer owns idempotency, nonce consumption, known/unknown signature recovery, grant expiry and revoke finality; Benten must not infer these from client claims.

The existing non-exported `packages/solana/src/spend-policy-draft.ts` and tests are **local research artifacts**, not Benten's product permission model. They return only `draft | rejected` with `autonomous_unavailable`, accept no client `remainingRaw`, and cannot transition to `active`, `submitted`, `revoked` or a grant. Proposed floor ratio, `maxSlippageBps`, nonce and quote timestamps lack owner attestation, independent price evidence and onchain uniqueness. Do not export or advertise this module; retain it only as negative-test/proposal-schema evidence pending a separate decision about its value. This is **not an implementation of spending authority**.

No Benten `agent_intents`, onchain policy cache, key vault or order ledger is proposed. The current read runtime needs no database. Future quote caching is **off by default**; only proven owner-independent intermediate state may be reused under the [wire contract](unsigned-acquisition-tool-contract.md), never an owner/ATA-specific template. The selected quote-BFF needs a narrow shared atomic TTL admission store for opaque-session hashes, CSRF verifier, consumed nonce, one in-flight lease and rate counters only; it is abuse-control state, not a quote, wallet, user-account or order database. The BFF is its sole writer. A test-only in-memory port makes no replica/restart claim; production requires the wire contract's fixed TTL/capacity, atomic admission/release, crash recovery, key-rotation and store-outage negatives. The external agent/provider owns private policy, transaction request idempotency, order ledger and receipts. Benten must not collect those records by default.

## 5. Review, operations, and explicit unknowns

Review Benten's **own** public data, route/quote and unsigned bytes against actual deployed DEX program identity, SDK/license, Token-2022 extensions, account metas and quote freshness. Re-run this after a mint, route, SDK, issuer terms or legal change. A dummy-owner simulation does not prove an external signer will enforce limits. If the Benten tool returns stale/unsafe context, disable that tool and keep facts-only service available. A third-party agent's lost key, spent allowance, unknown submission or pending revoke is handled by the user/provider; Benten may provide factual safety guidance but has no revoke button or incident control over it.

Benten costs remain unmeasured for public fact publication, RPC/quote reads, cache, legal review and security testing; record dated unit prices and bounded workload before a paid runtime choice. External policy-account rent, HSM/provider fees, agent infrastructure, transaction/priority fees and grant incident costs belong to the user/provider and must not be represented as zero or Benten-covered. Unverified Benten gates: size-specific xStock route, independent quote/minOut evidence, strict unsigned-payload audit, Token-2022 display conversion, rights/eligibility wording and host/API contract. None becomes a safe-autotrading claim through a documentation review.
