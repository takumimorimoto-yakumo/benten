The first experiment is **read-only/no-send**, performed for one fixed allowlisted mint and a bounded size grid: **1, 10, 50 and 100 USDC**, represented as `1000000`, `10000000`, `50000000`, `100000000` raw input units. These are measurement sizes, not financial advice or allowed spending. Use a public dummy address only if the provider requires a `taker`; no wallet connection, private key, ATA creation, signing, transaction submission or funded-owner simulation. If a provider cannot quote without an actual owner's accounts, record `owner_required_unverified` rather than substitute a real wallet. A positive reserve or a generic API success is insufficient. Public RPC/API requests are read-only external observations, not production enablement; rate-limit them.

The **internal research DTO** (not a public API) is a strict tagged union. `route` means a reviewed, exact policy route; `candidate_route` captures untrusted route evidence without promoting it into the allowlist. It is normalized for comparison, not for executable claims:

```ts
type ReviewedExactRoute = {
  cluster: "mainnet-beta"; genesis_hash: string;
  input_mint: string; output_mint: string;
  input_token_program: string; output_token_program: string;
  program_ids: string[]; pool_ids: string[]; vault_ids: string[];
  authority_ids: string[]; route_policy_revision: string;
  verified_slot: number;
};
type UntrustedRouteEvidence = {
  source: string; provider_route_id: string | null;
  claimed_program_ids: string[]; claimed_pool_ids: string[];
  claimed_account_ids: string[];
};
type FeeKind = "lp" | "protocol" | "transfer" | "network" |
  "priority" | "tip" | "integrator" | "ata_rent" | "other";
type FeeComponent =
  | { kind: FeeKind; status: "known"; mint: string; raw: string;
      basis: "input" | "output" | "transaction";
      source: string; reason: null }
  | { kind: FeeKind; status: "unknown"; mint: string | null;
      raw: null; basis: "input" | "output" | "transaction" | "unknown";
      source: string; reason: string }
  | { kind: FeeKind; status: "not_applicable"; mint: null;
      raw: null; basis: "unknown"; source: string; reason: string };
type Base = {
  version: "1";
  approach: "meteora_dlmm_direct" | "raydium_clmm_direct" | "jupiter_metis_build";
  input_raw: string; fees: FeeComponent[];
  price_impact: { status: "known"; bps: string; basis: string } |
    { status: "unknown"; reason: string };
  observed_at: string; source_revision: string | null;
  provider_request_id: string | null;
};
type VenueQuoteObservationV1 =
  | (Base & { status: "route_quote_observed"; route: ReviewedExactRoute;
      candidate_route: null; quoted_output_raw: string;
      quoted_output_basis: "gross" | "net"; net_output_raw: string | null;
      observed_slot: number; reason: null })
  | (Base & { status: "candidate_unverified"; route: null;
      candidate_route: UntrustedRouteEvidence; quoted_output_raw: string | null;
      quoted_output_basis: "gross" | "net" | "unknown";
      net_output_raw: string | null; observed_slot: number | null;
      reason: string })
  | (Base & { status: "unavailable"; route: null; candidate_route: null;
      quoted_output_raw: null; quoted_output_basis: "unknown";
      net_output_raw: null; observed_slot: null; reason: string });
```

`ReviewedExactRoute` includes cluster/genesis, exact input/output mint and token program, every program/pool/vault/authority, route-policy revision and a checked context slot. `UntrustedRouteEvidence` includes source/provider route ID and decoded program/pool/account IDs **as claims**, never a reviewed revision. `route_quote_observed` requires positive integer raw input/quoted output, an exact reviewed route, a real positive source slot/time and source revision; `candidate_unverified` requires a reason such as `source_slot_unproven` or `route_not_reviewed` even when provider output is positive; `unavailable` carries no quote or route. Each fee component has a distinct kind, mint, raw amount/status, basis and provenance: known amounts are nonnegative integer raw strings with an exact mint and known basis; unknown/not-applicable uses `raw:null` with a nonempty reason. Reject known-with-null-mint/raw, unknown-with-raw, negative/fractional amounts, duplicate same-kind/source fee rows and missing required fee-kind coverage in runtime validators and T-MV-03 negatives. Include Token-2022 transfer fee, LP/protocol fee, optional tip/integrator/priority/network fees and ATA rent **separately**; no fee is silently zero. `net_output_raw` is nullable until transfer fees/owner effects are proved; input debit ceiling and net output are separately compared, not inferred from one gross quote. A Jupiter multi-hop path must be fully decoded, never compressed to “Jupiter” as execution venue. Even `route_quote_observed` is not `quote_context_ready`, independent fair value or owner eligibility. Each adapter rejects unknown JSON fields, caps strings/arrays and uses BigInt. The evidence fixture retains only **sanitized public** route/slot/size, raw quoted and net amounts or explicit unknown, fee components, impact and calculation basis, failure reason, API/SDK revision, source/observation time, response digest and RPC/API call count/latency; no owner, credential, full provider response or transaction bytes. The fixture permits numeric re-audit without a stale quote being reused.

## 4. Security, policy migration, operations and cost

**Current public financial Web/API/MCP runtime remains snapshot-only.** The existing `@benten/solana` root is a separate **read-only RPC helper** for wallet holdings and pool inspection, not a snapshot-backed financial fact API; it has no sign/send path. A released live quote therefore requires the explicit versioned owner and quote-BFF migration in this revision; it is not added to current facts v1/v2 or local MCP. Benten research stays local no-send evidence; the generic connector is **externally owned and separately operated**. External agents call it directly. The selected Benten quote BFF is only a product consumer: short-lived browser session, strict exact pair/amount/mode, server-held scoped consumer token, no-store and no bytes. No private financial source, provider key or owner data enters a public bundle. A provider key is service access, never spending authority, and remains owner-side. Direct RPC needs genesis, fixed egress, timeout and redaction. An external user/agent key never enters Benten.

Rate/abuse controls are planned under the [unsigned contract](unsigned-acquisition-tool-contract.md): facts GET remains separate; future owner-direct high-cost routes authenticate each external caller with an individual owner-issued token bound to a registered consumer policy and stable per-caller/global minute/day quotas and active-admission concurrency across token rotation; Benten does not identify or proxy those callers in the initial mode. Neither access key grants funds or proves wallet ownership, residence or eligibility. Benten proposes no durable order, executable quote or user database; its production state is existing immutable public snapshots and product-policy revision. The external capability alone owns generic reviewed route policy and any minimal service-token/revocation/quota/audit namespace under a distinct public principal, never a Benten facts database or private trading/admin role. **Research-only** fixtures may retain sanitized public route/slot/size/raw numeric output, separate fee/impact values and basis, errors, source/API/SDK revision, response digest, time and latency as defined above, with no owner address, credential, full response or transaction bytes. Such historical numbers are never reusable quotes. RPO for orders is N/A because Benten never submits them. Failure returns `unavailable`/503 as specified by the future wire contract and leaves fact APIs intact; the owner disables a venue adapter, revalidates a fresh route and never replays an old quote.

Before paid/prod choice, measure per approach: RPC/API calls per size, p50/p95 latency, 429/5xx/error ratio, fresh quote age, owner Node bundle/build success (browser JS bytes only if a later optional wallet feature is approved), owner-dependent failure rate, current license/dependency SBOM and provider request-unit prices dated at decision time. Model low/base/peak traffic as `daily requests × calls/request × price/call × 30` plus host, cache, monitoring and fixed API plan; measure rate-limit headroom and privacy cost. Do **not** assume free tiers are zero-cost capacity or mix external wallet rent, network/priority fees or user losses into Benten's provider budget. The **single current research** `packages/solana/src/venues/route-policy.ts` owns only M2 observation revision and disable switch; the future independent capability must own one reviewed **production** route-policy source and Benten-bound consumer-policy revision. Transfer observations through reviewed evidence/fixture and revalidation, **not a runtime import of Benten's file or registry**. Disable only a failed provider adapter and keep verified facts available. No deployment, secret creation, legal approval, authority change or paid commitment is authorized by this plan.
